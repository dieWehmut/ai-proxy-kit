# OpenClaw 的 Sub2API 分组模型同步验收

用户请求：

> 如果是 sub2api 的，帮我设置成完整获取 key 的分组并自动选择分组的模型，而不用在 env 里面手动设置，这样我就能直接操作 sub2api 的分组直接切换模型。

> 我给的 key 分组一定对应只一个模型。

部署范围是 LXC 152、153 的 OpenClaw，以及 LXC 158 的 Sub2API。保留此前已经部署的 QQ thinking 提示过滤和各实例独立 Key。

## 必须满足的行为

1. 使用机器人自己的 Sub2API Key 读取其当前所属分组及可请求模型。分组身份和模型来自服务端，不将管理员凭据交给机器人，不硬编码 DeepSeek 或从通用模型列表随意取第一项。
2. 分组按唯一真实上游模型解析；多个合法别名指向同一模型时可归一。模型标识必须仍能由该 Key 请求。组的白名单、映射和权限参与解析，不能为了得到单模型修改现有共享生产组或生产 Key 归属。
3. 用户修改 Key 的所属分组，或修改其组的唯一模型配置后，运行中的 OpenClaw 下一次模型解析应获取新结果。已有 QQ 会话中的旧模型选择不得阻止 Sub2API 管理模式跟随分组切换；无需改 env、清聊天历史或手动重启网关。
4. 持久配置和模型目录自动同步，并有开机恢复方式。后台刷新用于持久状态；不能让较早的后台请求或过期的鉴权/模型缓存覆盖当前请求的新分组结果。
5. env 仍可保存连接地址、Key 及其他独立设置，但不再要求手写 Sub2API 模型或模型提供者选择变量。其他 provider 的选择以及关闭自动同步的实例不被该插件强制覆盖。
6. 无可用模型、多个真实模型、接口错误或网络暂态不能导致配置被清空或随机切换。保留最后有效配置和诊断；不要通过 QQ 发出本功能的系统诊断或此前的 thinking clamp 通知。普通模型回复与必要的用户可见错误仍正常处理。
7. 同时支持 152 的 Node 26/OpenClaw 新版，以及 153 的 Node 22/OpenClaw 2026.6.11。各实例独立 Key、来源白名单、QQ/MCP、thinking 偏好和其他设置保留。
8. Key 自省端点只提供该 Key 所属分组和模型所需的安全信息。保留吊销、过期、IP 白名单、用户和组权限检查；不泄漏 Key 值、账号凭据或其他 Key 的数据。元数据读取不要求消费余额为正。

## 部署和证据

- 修改前备份现有配置和被替换的程序；安装文件、同步配置和缓存以可恢复的方式更新。
- 分别运行两台安装版本的配置校验与真实网关 RPC，确保 API 请求确实经 Sub2API 的当前组转发。
- 用临时专用资源验证两台的同一会话在真实不同模型 A、B 之间切换：包括 Key 换组和只改组模型。检查 OpenClaw provider/model、Sub2API key/group 和实际 upstream model，不能用同一上游的两个别名代替模型切换验证。
- 测试不向真实 QQ 联系人发消息，不改其他用户的共享组；测试结束恢复机器人原有分组并删除仅测试新建的资源。
- 验证失败、空组、非 Sub2API 模式、并发新旧响应和重启恢复等必要边界。已有 QQ 提示过滤继续生效。
- 代码在独立分支分步验证、提交并推送到已有授权远程，保留可审查的后端补丁和构建/部署记录。不要夹带 `main` 上原有四个无关提交或运行凭据。
